## Decisões locais e o porquê

### Numeração Planner/Intent (Release 6/7) mantida conforme ADR-0031, não conforme a tabela recebida

O Roadmap recebido do Product Owner listava `6 — Intent Engine, 7 — Planner Engine`. [ADR-0031](../adr/0031-ordem-runtime-vs-desenvolvimento.md) já havia decidido deliberadamente o contrário (`6 — Planner, 7 — Intent`), com raciocínio específico (Planner construído primeiro com Intents mockadas). Como o roadmap recebido não trouxe justificativa para reabrir essa decisão — parece mais provável ser simplificação de uma tabela de alto nível do que uma intenção real de reverter o ADR — mantive a numeração de ADR-0031 e sinalizei a divergência explicitamente em `ROADMAP.md` e [ADR-0070](../adr/0070-roadmap-estendido-24-releases.md), em vez de decidir silenciosamente em qualquer direção.

### `EVENT_CATALOG.md` não duplica `DOMAIN_EVENTS.md`

As duas tabelas têm sobreposição real (evento/payload). Decisão: `DOMAIN_EVENTS.md` continua sendo a referência narrativa (por Engine, o porquê de cada evento); `EVENT_CATALOG.md` é a referência de **todos** os eventos de uma vez, com as colunas que faltavam. Um aponta para o outro; nenhum repete a explicação do outro. Alternativa descartada: fazer `EVENT_CATALOG.md` substituir `DOMAIN_EVENTS.md` — rejeitada porque `DOMAIN_EVENTS.md` já é referenciado por `IDENTITY_LIFECYCLE.md`, `ARCHITECTURE.md` e o próprio código, e reescrever/mover esse conteúdo geraria mais risco de quebra do que valor.

### `contracts/Identity.contract.yaml`: `Context`, não `Identity`, como tipo de saída

Achado real da validação cruzada: o contrato, escrito antes do código (Release 3, pré-implementação), usava "Identity" livremente para "o resultado da resolução" — na implementação real (Release 3A/3B), esse resultado é o tipo `Context` (imutável, ver ADR-0066), e `Identity` é o aggregate que o produz, não o valor em si. Corrigido para bater com o código; a mudança é só no Contract, nenhum código de produção mudou.

### `RegisterIdentity` não ganhou endpoint HTTP nesta Release

Notado durante a revisão: o caso de uso `RegisterIdentity` existe desde a Release 3B, mas `services/auth` nunca expôs um endpoint HTTP para ele (a Proposta da 3B nunca pediu — só login/logout/workspace/context). Não é uma lacuna desta Release corrigir, já que corrigi-la mudaria comportamento (endpoint novo), o que "sem mudar comportamento" desta Release 3.5 explicitamente não permite. Registrado como observação, não como pendência bloqueante — segue exatamente como estava.

## Achado real do teste em ambiente limpo

`docker compose down -v` + `build --no-cache` + `up`, seguido de uma tentativa de seed via `docker exec` **falhou** na primeira tentativa: `Table 'sigma_identity.tenants' doesn't exist`. Causa: `IdentityEngineModule::boot()` (onde as migrations rodam) só é executado quando `Bootstrap::fromManifestFile()` é chamado — e isso só acontece dentro de uma requisição HTTP real ao `services/auth` (arquitetura de front-controller, sem hook de inicialização de container). Em um ambiente genuinamente limpo, nenhuma requisição HTTP tinha acontecido ainda, logo nenhuma migration tinha rodado.

**Não corrigido nesta Release** (mudaria comportamento — ex: rodar migrations em um script de entrypoint do container, ou em um novo hook de "container startup" distinto de "primeira requisição") — registrado como característica conhecida do design atual, não um bug: depois da primeira requisição (mesmo uma que falhe, como um `/auth/context` com token inválido), o schema existe e permanece. Para um serviço HTTP real, isso é inofensivo na prática (health checks/primeira requisição real disparam o boot rapidamente) — mas é exatamente o tipo de risco que [ADR-0060](../adr/0060-release-dividida-em-sub-releases.md)/o Decision Log da 3B já haviam sinalizado como possível ("migrations dentro do Lifecycle podem não se encaixar bem no contrato `IModule` genérico"). Sinalizado para quando um Engine futuro com persistência for desenhado — considerar um hook de inicialização explícito, distinto de "primeira requisição", se isso importar para esse Engine.
