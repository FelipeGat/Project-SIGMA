## HTTP

### Critério 1 — `healthy`, não `Up` genérico

```
$ docker compose ps
SERVICE         STATUS
auth            Up 12 seconds (healthy)
gateway         Up 12 seconds (healthy)
mariadb         Up About an hour (healthy)
memory-worker   Up 12 seconds
redis           Up About an hour (healthy)
```

A transição `starting → healthy` foi observada de fato, com polling a cada 5s: ambos os serviços chegaram a `healthy` em **menos de 5s** — bem dentro do `start_period` de 30s.

### Critério 2 — comportamento com o banco fora do ar

Após `docker compose stop mariadb`:

| Serviço | `/health/live` | `/health/ready` | `/health/startup` |
|---|---|---|---|
| `gateway` (`:18080`) | **`200`** | `503` | `503` |
| `auth` (`:18081`) | **`200`** | `503` | `503` |

`POST /auth/login` respondeu `503` — a rota de domínio fica indisponível, a liveness não.

Ambos os containers foram marcados **`unhealthy` pelo Docker em ~25s** (`interval: 10s × retries: 3`), sem que nenhum processo morresse. É a primeira vez no projeto que o estado interno de um Module influencia uma decisão do orquestrador.

Após `docker compose start mariadb`, ambos voltaram a **`healthy` em 4s**, sem intervenção.

*(Uma primeira medição destes status, feita com um laço de shell mal construído, reportou `ready=200` incorretamente — contradizendo o `unhealthy` que o próprio Docker registrava. Refeita endpoint a endpoint; os números acima são os da medição corrigida.)*

## Pendências

1. **Os outros três pilares de [TELEMETRY.md](../../TELEMETRY.md)** — Metrics, Tracing, Audit — continuam sem implementação. Esta Release cobre health, o mínimo operacional, não observabilidade completa. Escopo da Release 23.
2. **Migrations ainda rodam na primeira requisição HTTP** — pendência aberta desde a 3B. O `start_period: 30s` a acomoda, não a resolve.
3. **Um Module que falhou no boot ainda exige restart do processo** — não há reconexão automática ao banco/Redis. O ganho desta Release é o orquestrador **saber**; agir automaticamente segue pendente desde a 4B.
4. **`/health/details`** (`status`, `modules[]`, `version`, `uptime`) continua no backlog.
5. **`start_period: 30s` foi calibrado por margem, não por medição do pior caso** — o ambiente medido subiu em <5s com cache quente. Uma primeira subida com banco vazio e migrations completas não foi cronometrada isoladamente.
6. **`memory-worker` sem healthcheck** — exceção consciente de ADR-0094; sua saúde real (está consumindo eventos?) permanece não observável.
7. **PHP 8.4 (ADR-0009) não validado**; **coverage não medida**.
8. **Nenhum healthcheck em ambiente de produção real** — só `docker compose` local. Kubernetes/deploy real é escopo da Release 23.
